# AI Agent 工作流

识别项目类型：`frontend`。

## 修改前

1. 先阅读现有目录结构和脚本。
2. 判断是否影响后端、前端、移动端、数据库、权限或 Docker。
3. 生成的检查脚本必须放在被检查的项目目录内。
4. 新增或修改代码注释时，统一使用中文。

## 修改后

1. 优先运行最具体的检查脚本。
2. 如存在 `scripts/check-all.sh`，再运行总检查。
3. 回复时说明改动文件、验证结果、风险，以及是否需要 Git 提交。

## Git 忽略规则

1. 依赖目录、构建产物、缓存、覆盖率、日志、本地环境变量和密钥文件默认不提交。
2. `.env.example`、`.env.*.example` 这类无密钥模板可以提交，用于说明必需配置项。
3. `package-lock.json` 属于可复现安装的锁文件，应随依赖变更提交。
4. IDE 目录默认按个人本地状态处理；如团队确实需要共享编辑器配置，应只提交明确可共享的模板文件。
5. 本项目前端构建产物写入相邻后端静态目录；当前仓库的 `.gitignore` 无法忽略仓库外路径，涉及发布构建时要同步检查后端仓库忽略规则。

## Git 提交流程

1. 提交前查看工作区状态和 diff，先排除无关变更。
2. 检查 diff 中是否出现密码、Token、私钥、真实地址、本地路径或环境标识。
3. 运行 `scripts/check-all.sh`；失败必须先修复或明确说明阻塞原因。
4. 使用 Conventional Commits 格式：`type(scope): 中文提交说明`，提交说明必须使用中文。
5. 提交保持原子化：功能、修复、重构、格式化、文档分别提交。
6. 对用户汇报时只说明文件类别和验证结果，不展开敏感路径或环境值。
